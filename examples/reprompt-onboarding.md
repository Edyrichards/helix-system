# Example: Vague Input → Helix Reprompt → Design Reasoning

## Raw user input

> make onboarding better

## Helix behavior

Helix does **not** immediately invent screens. It runs intake and detects critical gaps.

## Clarifying questions

1. What is the target user/persona?
2. What is the current onboarding flow or artifact?
3. What is the success metric for "better" (activation, completion, trial start, revenue, reduced support)?

## If the user answers

> B2B founder using a project management AI tool. Current flow asks for signup first, then workspace setup, then invite team. Better means more people reach their first AI-generated project plan.

## Reprompted working brief

Act as a senior product designer, behavioral UX strategist, and frontend verifier. Improve onboarding for a B2B founder using an AI project management tool. The activation event is the user's first AI-generated project plan. Current flow asks for signup before value, then workspace setup, then invite team. Redesign the onboarding so users preview value before commitment, reduce setup friction, and reach activation faster.

Use:
- design reasoning engine
- advanced design psychology
- design-system-first
- browser visual verification

Produce:
1. behavioral hypothesis
2. friction map
3. revised flow
4. screen/system implications
5. verification plan

## Behavioral hypothesis

If we let founders generate a sample project plan before full signup, then more users will complete onboarding because reciprocity and value-before-ask reduce signup-wall anxiety, measured by more users reaching the first AI-generated plan.

## Expected artifact

- UX flow
- copy strategy
- design system decisions
- desktop/mobile screenshots if implemented
- psychology score using rubric v3
