# Helix Conversion UX Models

Purpose: provide ethical behavioral models for conversion and activation design.

## Ethical line
Use psychology to reduce confusion, reveal value, increase control, and support informed action. Never use it to hide cost, fake scarcity, manufacture proof, or trick users.

## Conversion sequence
For most product pages:
1. Recognition: name the user's real situation.
2. Relief/value: show the product explains or solves it.
3. Proof: demonstrate a concrete outcome or preview.
4. Risk reduction: answer the next objection near the ask.
5. Small commitment: ask for the smallest meaningful action.
6. Reinforcement: show what happens next.

## Screen-level checks
- Does the first fold answer "is this for me?"
- Does it show value before asking for commitment?
- Does it make the next action easier than doing nothing?
- Does it reduce the largest trust objection at the point of friction?
- Does it avoid making claims the product cannot prove?

## Common patterns
### Demo-before-signup
Good for products where users fear effort or data access.
Structure: interpreted sample result -> low-risk CTA -> privacy line.

### One-decision framing
Good for complex dashboards.
Structure: single insight -> cause -> recommended next decision -> follow-up loop.

### Import-first safety
Good for finance/productivity tools.
Structure: local/import/manual start -> optional connection later -> export/control.

### Household/shared language
Good for shared decision tools.
Structure: neutral framing -> cause separation -> one shared review -> non-blame next step.

## Anti-patterns
- louder CTA without value clarity
- fake testimonials/logos
- countdown timers without real scarcity
- dashboard detail before user understands the product job
- fear-first copy without user control
